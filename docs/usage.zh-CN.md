# 使用与配置

首次安装和验证请参阅 [README](../README.md)。

## 桌面插件

插件使用 DSH 桌面端配置的模型和凭证。当前适配依赖的 DSH 接口版本为 `0.2.2-rc.1`。使用更早版本或第三方桌面客户端时，需要核对[宿主接口兼容性](architecture.md#deployment-modes)。

### 使用命令行安装或升级

在 DSH 桌面客户端的应用菜单中选择「管理 dsh 命令…」。安装后打开新终端，用 `dsh --version` 确认命令可用。安装或升级插件前先完全退出桌面客户端。Windows 可以通过系统托盘的右键菜单退出。

将下例中的路径换成实际的 `.tgz` 安装包完整路径。打包命令见 [README](../README.md)。

```powershell
dsh plugin --profile desktop add 'C:\Downloads\dingtalk-dsh-0.2.14.tgz'
```

### 可选设置

| 设置 | 默认值及用途 |
| --- | --- |
| 数据目录 | DSH 用户数据目录下的 `dingtalk-dsh/desktop`，存放待处理消息及会话映射。可填写完整目录路径。 |
| 工作区 | 数据目录下的 `workspace`。可填写完整目录路径。 |
| 任务超时（秒） | 300 秒，可设为 10 至 3600 秒。 |
| 在钉钉发送进度 | 默认关闭。开启后发送开始处理提示和 DSH 任务清单的完成数，开关即时生效。 |

「启用钉钉桥接」默认关闭。关闭时会断开 Stream 连接，保留插件配置和会话映射。桥接开启时保存连接相关配置会触发重连。

Client Secret 存在 DSH 的本机凭证库中，详情页只显示保存状态。更换钉钉应用凭证时，先关闭桥接，保存新的 Client ID 和 Client Secret，再开启桥接。

### 在桌面查看钉钉会话

首次收到消息后，插件会在所选工作区创建 DSH 会话。已有工作区沿用原名称，新建工作区名为「钉钉对话」。新会话使用桌面的模型和智能体预设，工作区中的 `AGENTS.md` 和技能按该预设加载。恢复会话时沿用已记录的模型和预设，旧会话缺少预设记录时使用桌面当前默认预设。

普通钉钉消息的气泡上方会显示聊天来源和发言人，可展开查看元数据。处理中收到的同一聊天补充消息可加入当前会话，其上下文可在「轨迹」中查看。桌面端生成一条正文后，桥接会尝试发送这条正文，用户可能收到多条回复。CLI 独立服务回传最终回答。

## CLI 环境变量

从仓库根目录执行 `npm.cmd ci`，完整安装依赖，其中包括独立入口使用的 SDK。CLI 读取程序目录下的 `.env`，进程环境变量优先。相对路径以程序目录为基准。

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `DINGTALK_CLIENT_ID` | 必填 | 钉钉企业内部应用的 AppKey。 |
| `DINGTALK_CLIENT_SECRET` | 必填 | 钉钉企业内部应用的 AppSecret。 |
| `DEEPSEEK_API_KEY` | 必填 | 独立运行时使用的 DeepSeek API Key。 |
| `DSH_MODEL` | `deepseek-flash` | 独立运行时的模型标识。 |
| `BRIDGE_DATA_DIR` | `.data` | CLI 数据根目录。 |
| `DSH_WORKSPACE` | 数据目录下的 `workspace` | 钉钉会话使用的文件工作区。 |
| `DSH_RUN_TIMEOUT_MS` | `300000` | 单次任务的最长等待时间，允许 10000 至 3600000 毫秒。 |

桥接连接钉钉后，CLI 会在收到第一条任务时按需启动 DSH。

## 会话数据、升级和备份

- **CLI 升级**时保留 `.env` 和现有数据目录（默认 `.data`），其中 `bridge.sqlite` 保存会话映射和待处理任务，`dsh/` 保存 SDK 运行时数据。更新源码后重新构建，再启动服务。
- **桌面插件升级**时保留原有数据目录和工作区。默认的映射数据库是 DSH 用户数据目录下的 `dingtalk-dsh/desktop/bridge.sqlite`。已配置的旧版安装继续使用原有目录，在插件页面保存新凭证后优先使用新凭证。卸载插件会停止桥接，已持久化的 DSH 会话由桌面客户端保留。
- **切换模式**时先停止原入口，并为新模式使用它自己的数据目录。切回原模式时使用原目录即可恢复原映射。桥接会拒绝打开属于另一种模式的映射数据库。
- **备份前**先停止对应的桥接服务或关闭桌面桥接。数据目录可能含有聊天内容、回复地址和会话映射，访问权限应限于运行者。

## 常见问题

| 现象 | 检查项 |
| --- | --- |
| 开关已打开，日志还没有显示「钉钉连接已建立」 | 检查 AppKey 和 AppSecret、机器人 Stream 模式、应用发布状态和网络。桌面开关显示的是保存的启用状态，实际连接以日志为准。 |
| 私聊有回复，群聊没有 | 确认机器人在群内，应用可使用范围包含对应用户，并在群里 @机器人。 |
| 钉钉已连接，但任务没有返回答案 | 先用一条普通文字消息测试。桌面模式检查默认模型和智能体预设是否可用，并在桌面会话查看是否等待审批。CLI 模式检查 `DEEPSEEK_API_KEY` 和 `DSH_MODEL`。其他聊天有任务时，消息可能仍在排队。 |
| 提示任务超时或中断 | 先确认任务是否已经执行，再决定是否重发。重启后，桥接会继续处理尚未执行的队列。 |
| 回复地址过期，结果未送达 | 在同一钉钉聊天收到新消息并取得有效回复地址后，桥接会尝试补发已保存的结果。 |
| 提示数据目录已用于另一种模式 | 给当前模式配置独立的数据目录。需要继续原会话时，切回原模式并使用原来的数据目录。 |
